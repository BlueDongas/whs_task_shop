# 보안 체크리스트

## 인증 및 세션

- [x] 비밀번호를 평문으로 저장하지 않는다.
- [x] 로그인 실패 시 사용자 존재 여부가 드러나지 않는 공통 메시지를 사용한다.
- [x] 세션 쿠키에 HttpOnly를 적용한다.
- [x] SameSite 쿠키 정책을 적용한다.
- [x] 로그아웃은 POST 요청으로 처리한다.

## 접근 통제

- [x] 비로그인 사용자는 상품 등록·수정·삭제를 할 수 없다.
- [x] 판매자만 자신의 상품을 수정·삭제할 수 있다.
- [x] 판매자만 자신이 판매하는 상품의 구매 요청을 승인·거절할 수 있다.
- [x] 사용자는 자신의 상품을 구매 요청할 수 없다.
- [x] 판매 완료 상품에는 구매 요청을 보낼 수 없다.

## 입력 및 출력

- [x] 모든 상태 변경 폼에 CSRF 토큰을 사용한다.
- [x] 상품명과 설명의 최대 길이를 제한한다.
- [x] 가격 범위를 서버에서 검증한다.
- [x] Jinja2 자동 이스케이프를 유지한다.
- [x] 사용자 입력에 `safe` 필터를 사용하지 않는다.
- [x] ORM을 사용해 SQL Injection 위험을 줄인다.

## 데이터 및 설정

- [x] SECRET_KEY를 환경변수로 분리한다.
- [x] `.env`와 데이터베이스 파일을 Git에서 제외한다.
- [x] 중복 구매 요청을 애플리케이션과 DB에서 모두 차단한다.
- [x] 승인된 구매 요청 외의 대기 요청을 자동 거절한다.

## 배포 시 추가 항목

- [ ] HTTPS를 적용한다.
- [ ] `SESSION_COOKIE_SECURE=True`를 적용한다.
- [ ] Debug 모드를 비활성화한다.
- [ ] 리버스 프록시와 요청 속도 제한을 적용한다.
- [ ] 운영 데이터베이스 백업 정책을 수립한다.
