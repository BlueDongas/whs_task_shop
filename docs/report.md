# Tiny Second-hand Shopping Platform 개발 보고서

## 1. 프로젝트 개요

본 프로젝트는 Flask 기반의 소규모 중고거래 플랫폼을 설계하고 구현한 결과물이다. 사용자는 회원가입과 로그인 후 상품을 등록할 수 있으며, 다른 사용자의 상품에 구매 요청을 보낼 수 있다. 판매자는 자신에게 접수된 구매 요청을 승인하거나 거절할 수 있다.

GitHub Repository: `<GITHUB_REPOSITORY_URL>`

## 2. 개발 목표

- 최소 기능을 갖춘 중고거래 플랫폼 구현
- 요구사항 분석부터 테스트 및 유지보수까지 전 과정 문서화
- 인증·인가, 입력값 검증, CSRF, XSS, IDOR 등 주요 웹 보안 약점 방지
- WSL 환경에서 쉽게 재현 가능한 실행 절차 제공
- AI 도구를 활용하되 결과를 직접 검토하고 수정

## 3. 요구사항 분석

### 3.1 기능 요구사항

1. 사용자는 회원가입, 로그인, 로그아웃할 수 있어야 한다.
2. 로그인한 사용자는 상품을 등록할 수 있어야 한다.
3. 상품 작성자는 자신의 상품만 수정하거나 삭제할 수 있어야 한다.
4. 사용자는 다른 판매자의 판매 중 상품에 구매 요청을 보낼 수 있어야 한다.
5. 판매자는 구매 요청을 승인하거나 거절할 수 있어야 한다.
6. 승인된 상품은 판매 완료 상태로 변경되어야 한다.
7. 상품 검색 및 사용자별 거래 내역 조회 기능을 제공해야 한다.

### 3.2 비기능 요구사항

- WSL Ubuntu와 Python 가상환경에서 실행 가능해야 한다.
- 실행 방법을 README에 명시해야 한다.
- SQLite를 사용해 별도 DB 서버 없이 실행 가능해야 한다.
- GitHub Public Repository로 배포 가능해야 한다.
- 테스트 코드와 보안 체크리스트를 제공해야 한다.

### 3.3 보안 요구사항

- 비밀번호는 단방향 해시로 저장한다.
- 모든 상태 변경 요청에 CSRF 보호를 적용한다.
- 자원 소유권 검사를 통해 IDOR를 방지한다.
- 서버 측 입력값 검증을 수행한다.
- 사용자 입력 출력 시 HTML 이스케이프를 수행한다.
- Secret Key를 소스 코드 저장소에 포함하지 않는다.

## 4. 시스템 설계

### 4.1 아키텍처

```text
Web Browser
    |
    v
Flask Routes / Blueprints
    |
    +-- Authentication
    +-- Product Management
    +-- Purchase Transactions
    |
    v
SQLAlchemy ORM
    |
    v
SQLite Database
```

### 4.2 모듈 구성

- `auth.py`: 회원가입, 로그인, 로그아웃
- `products.py`: 상품 CRUD, 검색, 마이페이지
- `transactions.py`: 구매 요청, 승인, 거절
- `models.py`: User, Product, PurchaseRequest 모델
- `forms.py`: 입력값 검증 및 CSRF 폼
- `tests/`: 인증, 권한, 거래 무결성, XSS 테스트

### 4.3 데이터베이스 설계

#### User

- id: 기본키
- username: 고유 아이디
- password_hash: 해시된 비밀번호
- created_at: 가입 시각

#### Product

- id: 기본키
- title: 상품명
- description: 상품 설명
- price: 가격
- status: SELLING 또는 SOLD
- seller_id: 판매자 외래키
- created_at: 등록 시각

#### PurchaseRequest

- id: 기본키
- product_id: 상품 외래키
- buyer_id: 구매자 외래키
- status: PENDING, ACCEPTED, REJECTED
- created_at: 요청 시각

## 5. 구현 과정

### 5.1 인증 구현

Flask-Login을 이용해 세션 기반 인증을 구현하였다. 비밀번호는 Werkzeug의 `generate_password_hash()`를 사용해 해시로 저장하고, 로그인 시 `check_password_hash()`로 검증하였다.

### 5.2 상품 관리 구현

로그인한 사용자는 상품을 등록할 수 있다. 수정과 삭제 라우트에서는 URL의 상품 ID만 신뢰하지 않고, `product.seller_id`와 `current_user.id`를 비교하여 판매자 본인인지 검사한다.

### 5.3 거래 구현

구매자는 다른 사용자의 판매 중 상품에 구매 요청을 보낼 수 있다. 판매자가 요청을 승인하면 상품 상태를 SOLD로 변경하고, 동일 상품의 나머지 대기 요청은 REJECTED로 변경한다.

## 6. 확인한 보안 약점 및 개선

### 6.1 평문 비밀번호 저장

초기 단순 구현에서는 비밀번호를 그대로 저장할 가능성이 있었다. DB 유출 시 계정 정보가 즉시 노출되는 문제가 있으므로 단방향 비밀번호 해시로 변경하였다.

### 6.2 IDOR

상품 수정·삭제 URL에 상품 ID가 포함되기 때문에 다른 사용자가 ID를 변경해 접근할 수 있다. 이를 방지하기 위해 상품 소유자와 현재 로그인 사용자를 서버에서 비교하고, 일치하지 않으면 HTTP 403을 반환한다.

### 6.3 CSRF

상품 삭제, 구매 요청, 승인, 거절과 같은 상태 변경 요청에 CSRF 토큰이 없으면 사용자가 의도하지 않은 요청이 실행될 수 있다. Flask-WTF를 적용하여 모든 POST 폼에 CSRF 토큰을 포함하였다.

### 6.4 XSS

상품명과 설명에 스크립트 또는 이벤트 핸들러를 입력할 수 있다. Jinja2의 자동 이스케이프를 유지하고 `safe` 필터를 사용하지 않아 브라우저에서 코드가 실행되지 않도록 하였다.

### 6.5 SQL Injection

문자열 연결 방식으로 SQL을 작성하지 않고 SQLAlchemy ORM을 사용하였다. 검색 기능도 ORM 조건식을 통해 처리하였다.

### 6.6 중복 및 비정상 거래

사용자가 자신의 상품을 구매하거나, 판매 완료 상품에 구매 요청을 보내거나, 동일 상품에 중복 요청하는 것을 서버에서 차단하였다. 중복 요청은 데이터베이스 유일 제약으로도 방어하였다.

### 6.7 Open Redirect

로그인 후 `next` 파라미터를 그대로 사용하면 외부 사이트로 이동시킬 수 있다. 요청 호스트와 대상 URL의 호스트를 비교해 내부 URL만 허용하였다.

### 6.8 비밀정보 노출

SECRET_KEY와 데이터베이스 설정을 `.env`로 분리하고 `.gitignore`에 추가하였다. GitHub에는 값이 비어 있는 `.env.example`만 포함한다.

- 잘못된 로그인 처리
- 타인의 상품 수정·삭제 차단
- 자신의 상품 구매 차단
- 판매자 이외 사용자의 승인 차단

## 10. 결론

Tiny Market은 소규모 과제에 적합한 Flask 기반 중고거래 플랫폼이다. 기능 구현뿐 아니라 인증, 권한 검증, CSRF, XSS, SQL Injection, Open Redirect, 거래 무결성 등의 보안 요소를 개발 과정에 반영하였다. README와 자동 테스트를 통해 다른 환경에서도 실행과 검증이 가능하도록 구성하였다.
